# medusa-platform

Terraform that provisions everything [`medusa-backend`](https://github.com/fahlula/medusa-backend)
needs: a Cloudflare Tunnel, a small GCE instance behind it, and the keyless federated
identity that lets GitHub Actions deploy to it.

## Architecture

```
                 ┌─────────────────────────────────────────┐
  client ──TLS──▶│ Cloudflare edge                          │
                 │ api-stg-medusa.fabianalula.site (proxied)│
                 └────────────────┬────────────────────────┘
                                  │ tunnel (outbound-initiated)
                 ┌────────────────▼────────────────────────┐
                 │ GCE e2-micro · COS · 10 GB pd-standard   │
                 │  ┌────────────┐      ┌────────────────┐  │
                 │  │ cloudflared│─────▶│ app :8080 (bun)│  │
                 │  └────────────┘      └────────────────┘  │
                 │  no static IP · no inbound firewall rule │
                 └────────────────▲────────────────────────┘
                                  │ IAP (35.235.240.0/20, IAM-authenticated)
                       GitHub Actions deploy
```

The instance never listens on a public port. `cloudflared` dials **out** to Cloudflare and
holds the connection open, so inbound traffic arrives through a connection the box itself
opened. The only ingress firewall rule is Google's IAP range on port 22, and that traffic
is already IAM-authenticated before it arrives. Everything else inbound is denied
explicitly.

## What it creates

| Provider | Resource | Why |
|---|---|---|
| Cloudflare | Zero Trust tunnel + ingress config | Public reachability without exposing the origin |
| Cloudflare | Proxied `CNAME` → `<tunnel>.cfargotunnel.com` | `api-stg-medusa.fabianalula.site` |
| GCP | Artifact Registry (keeps 10 newest) | Image storage |
| GCP | Secret Manager entry | Tunnel token at rest |
| GCP | VPC, subnet, 2 firewall rules | IAP-only ingress, deny-all fallback |
| GCP | e2-micro + 10 GB disk (COS, Shielded VM) | Runs app + connector |
| GCP | 2 service accounts | Instance identity, CI deployer |
| GCP | Workload identity pool + provider | Keyless CI auth, scoped to one repo |
| GitHub | 6 Actions secrets + `stg` environment | Deploy credentials, written by Terraform |

## The secret path

The tunnel token is generated by Cloudflare, read by Terraform, and written straight into
Secret Manager — it is never committed and never placed in instance metadata. At boot the
instance exchanges its own identity for an access token at the metadata server and reads
the secret itself. A process on the box without `secretAccessor` cannot get it.

```
Cloudflare tunnel token
  └─▶ google_secret_manager_secret_version   (encrypted at rest)
        └─▶ instance SA (secretAccessor on this one secret only)
              └─▶ /var/lib/medusa/fetch-token.sh at boot → cloudflared
```

CI has no key at all. The organization enforces
`constraints/iam.disableServiceAccountKeyCreation`, so instead of a JSON key this stack
provisions **Workload Identity Federation**: GitHub presents its OIDC token, GCP exchanges
it for a short-lived credential, and an `attribute_condition` restricts that trade to this
one repository. The two values written to GitHub — the provider resource name and the
service-account email — are identifiers, not secrets.

```
GitHub Actions OIDC token  (per-run, minted by GitHub)
  └─▶ workload identity pool provider
        └─ attribute_condition: assertion.repository == "fahlula/medusa-backend"
              └─▶ deployer SA, short-lived token, no key to leak or rotate
```

## Scoping

| Identity | Roles |
|---|---|
| Instance SA | `secretAccessor` (one secret), `artifactregistry.reader` (one repo), `logging.logWriter` |
| Deployer SA | `artifactregistry.writer` (one repo), `compute.instanceAdmin.v1`, `iap.tunnelResourceAccessor`, `compute.osLogin` |

Neither is a project-wide admin. Registry and secret grants are resource-scoped, not
project-scoped.

## Usage

```bash
cd terraform
cp terraform.tfvars.example terraform.tfvars   # gitignored
terraform init
terraform plan
terraform apply
```

Prefer environment variables over the tfvars file for anything sensitive:

```bash
export TF_VAR_cloudflare_api_token='…'
export TF_VAR_github_token="$(gh auth token)"
```

### Prerequisites

| | |
|---|---|
| Billing | An **open billing account** linked to the GCP project |
| ADC | `gcloud auth application-default login` — Terraform does not read the gcloud CLI credential |
| Cloudflare token | `Zone:DNS:Edit` + `Account:Cloudflare Tunnel:Edit` |
| GitHub PAT | `repo` scope, to write Actions secrets |

### Remote state

State contains the tunnel token in plaintext. The GCS backend in
`versions.tf` is commented out until the bucket exists — **uncomment it before any
shared use**, and never commit `*.tfstate`.

## Repository secrets this stack needs

| Secret | For |
|---|---|
| `GCP_PROJECT_ID` | Target project |
| `CLOUDFLARE_API_TOKEN` | Tunnel + DNS management |
| `CLOUDFLARE_ACCOUNT_ID` | Account that owns the zone |
| `CLOUDFLARE_ZONE_ID` | `fabianalula.site` |
| `TF_GITHUB_TOKEN` | PAT used to write secrets into `medusa-backend` |
